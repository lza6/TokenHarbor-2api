## 0. 现状总结（审计基线，2026-09-25）

- 版本：v0.2.8（Rust 1.95 / axum 0.8 / tokio / rusqlite），main 分支 c5da765 干净
- 功能已闭环：OpenAI chat/responses + Anthropic messages 双向 SSE、23 模型目录、多凭证池、自动续期、Web 面板门锁、管理端点双认证、登录防爆、CORS、错误脱敏、CI/CD
- **核心缺口：测试覆盖率 24.45%（HTTP/协议/续期/限流/并发/UI 认证全部 0%），CI 门槛 20% 形同虚设**
- 真实 E2E：本地 16 项已过（鉴权/防爆/导入校验/UI 签发/CORS）；对话类链路因无凭证标记 not_run（不伪造）
- 线上 52.141.3.10：v0.2.8 active、1 凭证、23 模型、无 key → /v1/models 与 /api/tokens 均 401（安全基线 ✅）

### 0.1 一句话结论
**网关功能完整、安全基线不错，但工程质量（测试覆盖率、可运维性、参数校验顺序、配置死项）是下一阶段唯一真正要解决的问题。**

### 3.2 关键技术点
- **集成测试**：`axum` + `tower::ServiceExt::oneshot`，用 `build_router(AppState{...})` 直接打请求，不依赖真实网络；上游调用用 mock（`upstream` 提供可替换 http 客户端 trait，或本地起 `axum` 假上游）。
- **SSE 测试**：把上游 SSE 写进字符串流（`Body::from` / `futures::stream::iter`），驱动 `openai_events` 收集全部 chunk，断言事件序列。
- **时间注入**：`ratelimit`/`web_pool` 的冷却逻辑引入 `Clock` trait（或参数化 now），避免真实 sleep。
- **覆盖率门禁**：P1 完成时 `cargo llvm-cov --lib --tests --fail-under-lines 90` 必须通过；CI 同步改 90。
- **禁止**：为刷覆盖率写空断言；必须每个用例有真实行为断言。

### 3.3 验收
- `cargo llvm-cov --lib --tests` 行覆盖率 ≥90%
- 新增测试文件：`tests/api_integration.rs`、`tests/sse_transform_test.rs`、`tests/refresh_parse_test.rs`、`tests/auth_ratelimit_test.rs`、`tests/upstream_mock_test.rs` 等

## 6. P4 — 安全与运维加固（1-2 天）

### 6.1 建议项（按价值排序）
- [ ] **全局限流中间件**：per-IP + per-key 滑动窗口（登录端点现有 LoginGuard 保留；新增 `/v1/*` 与 `/api/*` 通用限流），参数可配置（`rate_limit_rps`/`burst`），避免共享上游被打爆
- [ ] **运行时 api_keys 持久化**：`generate/set` 后写 `data/api_keys.json`（chmod 600），重启不丢；面板提示「生成的 key 不会写回 config.json」
- [ ] **ui_password 迁移到环境变量/密钥文件**：config 支持 `UI_PASSWORD`（已支持环境变量覆盖），README 强调生产用环境变量，避免明文入库
- [ ] **telemetry 落地**：把 `telemetry_path` 用起来——写入请求数/状态码/延迟/上游 429 计数（rusqlite 已有依赖），供 `/api/stats` 与运维查询；或明确删除该字段
- [ ] **CSRF 补充**：管理端点用 Cookie 认证时，`SameSite=Lax` 已挡跨站 POST，但建议对 `/api/config/api-key`、`/api/tokens/delete` 增加显式 `X-Requested-With` 校验或 CSRF token（可选，标注权衡）
- [ ] **日志分级**：`tracing` 已接 redact，补 request/response 摘要日志（方法/路径/状态/耗时），敏感字段走 redact

### 6.2 验收
- 压测 100 并发时 `/v1/*` 触发限流 429（可配置）；重启后 api_keys 仍在；telemetry 表有写入

## 8. 维护与迭代规范（长期）

- **每次改动**：先跑 `cargo test` + `cargo clippy`，覆盖影响模块；改协议/认证必须补对应测试
- **CI 门槛**：覆盖率 90%，clippy -D warnings，audit 0，fmt 必过
- **凭证安全**：Cookie/key 永不进仓库（.gitignore 已含 data/、config.json）；导入/续期日志走 redact
- **上游协议漂移**：TokenHarbor 站点 JS/接口可能变，`models.rs` 免费窗口、`upstream.rs` 端点要能快速改；`P3-5` 的 models 刷新机制上线后漂移自动感知
- **文档同步**：每次发版更新 README/CHANGELOG/docs/计划书证据，保持「代码 ↔ 文档 ↔ 实测证据」一致
- **禁止**：无验证声称成功；mock 顶替真实 E2E；git add . / force push
